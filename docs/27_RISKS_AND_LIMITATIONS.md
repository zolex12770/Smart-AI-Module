# Risks & Limitations

Honest accounting, kept current. See [[FINAL_AUDIT|FINAL_AUDIT]] (now exists, produced at Phase 15, 2026-09-02) for the point-in-time audit and what it found/fixed; this file tracks standing, structural risks going forward.

## Structural limitations (true regardless of how well we build)

- **No provider can generate a single 20+ minute video clip as of this research (2026).** Confirmed concretely: real per-call duration ceilings across every provider surveyed sit between 5 and 25 seconds (Veo 3.1: 8s; Sora 2: up to 12s, Sora 2 Pro: up to 25s; Runway Gen-4: up to 10s; Luma Ray2: up to 9s; Kling: 5s default/10s max) — see [[06_VIDEO_GENERATION_RESEARCH]]. "Extend" features chain multiple short calls; they do not raise the real per-call ceiling. Long-form video is necessarily a scene-decomposition-and-assembly pipeline ([[07_LONG_RUNNING_JOB_ARCHITECTURE]]), not a native capability of any vendor API. We will not claim otherwise in product copy.
- **Live illustration of why this platform is provider-agnostic:** research (2026-08-31) found OpenAI's entire Sora 2 API is scheduled to shut down September 24, 2026 — roughly three weeks out. A platform hardcoded to one video vendor would face an imminent forced rewrite; the `VideoProvider` abstraction ([[06_VIDEO_GENERATION_RESEARCH]]) exists precisely so a vendor deprecation is a config/adapter change, not an architecture change. This is also one more reason ADR-009 (mock-first, real integration only once credentials exist) is the right sequencing — we are not currently exposed to this deprecation at all.
- **Cross-scene visual/character consistency in generated video is best-effort, not guaranteed**, even with reference images/seeds/character sheets. This is a known limitation of current generative video models, not a bug in our orchestration.
- **RAG retrieval quality is bounded by chunking/embedding choices and can miss or misattribute information**, especially on documents with complex layout (tables, scanned images). Citations reduce but do not eliminate the risk of a wrong answer being presented as document-grounded. As of Phase 6, this is more pronounced than the general case: the embedding is a real deterministic feature-hashed vector (lexical/keyword overlap), not a learned semantic one ([[26_DECISIONS]] ADR-026) — a question phrased with different words than the source document may retrieve nothing relevant even though the answer exists in the corpus. Plain text/Markdown, real PDF, and real DOCX ingest today (docs/26_DECISIONS.md ADR-036); CSV is not yet parsed, and PDF/DOCX extraction is plain paragraph text only — no layout/table/heading-structure awareness, and no OCR for scanned PDFs.
- **Prompt injection cannot be fully eliminated**, only mitigated (trust-level separation, approval gates on high-risk actions per [[13_SECURITY_ARCHITECTURE]]). Any agent that reads untrusted content and can take actions has residual risk.
- **Mock providers validate interface/orchestration correctness, not real output quality.** Passing all tests against `llm-mock`/`image-mock`/`video-mock` does not prove the real provider integration behaves identically — real-provider validation is a separate, explicit step once credentials exist (ADR-009).

The reverse of the row above: under-counting rather than not counting.
- **A failed usage-record write is reported to the client as a provider failure** (ADR-045), after the successful answer has already been streamed to them — the ledger write sits inside the same try block as the provider call.

## Explicitly out of scope for the initial working system (see [[01_REQUIREMENTS]] non-goals)

- Foundation model training/fine-tuning.
- Public multi-tenant self-serve billing.
- Any real image/video/cloud spend without explicit, separate user authorization at that specific step.
- **Cloning a repository into the agent's workspace — deliberately absent (ADR-142).** A coding
  task is seeded by writing named files (`POST /api/v1/workspace/files`, containment-checked
  against the same boundary the agent's own tools use). `git clone` would mean outbound network
  access to an arbitrary URL from a model-driven environment, credential handling for private
  repositories, and an unbounded amount of data landing on disk — three security decisions, each
  larger than the feature. What exists is the smaller honest primitive; it does not pretend to be
  a VCS integration.
- **Password RESET ("forgot password") — deliberately absent, not overlooked (ADR-127).** A reset
  flow is a way to take over an account using only an email address, so it is exactly as strong as
  the channel that delivers the token. This deployment has no mail transport, no domain and no
  sender reputation, and a reset endpoint that logged a token to the console or returned it in the
  response would be an authentication bypass wearing the costume of a feature. What EXISTS instead:
  a signed-in user can change their own password (`POST /api/v1/auth/password`, current password
  required), see their live sessions and end any of them. A user who is locked out entirely needs
  an operator, and that is the honest state of it rather than a half-built flow.
